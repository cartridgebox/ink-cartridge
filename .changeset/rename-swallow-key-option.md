"@cartridge-engine/keyboard-engine": minor

Rename the composition swallow option, fix chain restarts and screen scoping, give layer sequences priority over sibling bindings, let the mouse GC cleanup registry collect the instance, reassemble mouse reports split across reads, apply `when` to sequences that also have `focusId` or `stopsWorkingAfterLayerAppearing`, and treat real focus changes as the boundary for pending sequences.

### Added
None

### Changed
- The composition and mapping option is now `SwallowKeyWhenChainInterrupted`. The old name stated the opposite of the flag's behavior: `true` swallows the interrupting key, while the default (`false`) releases it to lower pipeline stages. The implementation and documentation already used that polarity, so only the name changes.
- The internal `KeyOutcome` field is now `swallow`, matching the mapping path, so `processPending` no longer returns a value named `release` whose `true` means "consumed".
- `processPending` and `processMappingKeyPending` report `"none" | "consumed" | "released"` instead of a boolean, so the caller can tell "the key is unrelated to the pending chain" from "the key took part in the chain and was settled by it".

### Fixed
- A key that settles a pending composition chain — `execute` returned `null`, `isEndKey` matched, or a value guard rejected it — is now only released to lower pipeline stages and is no longer re-read as a chain head. When the same physical key was also registered as a head (`optional: true` or `needs: []`), that re-read ran a second callback, emitted `completed` followed immediately by `started`, and left a phantom chain pending until its timeout. With an `exclusive` head the phantom chain also swallowed every later key until that timeout, and the timeout added a second entry to the undo buffer.
- A key that completed a mapping sequence whose target chain was interrupted is likewise released instead of being re-read as a composition head.
- Composition entries that differ only by `category` are no longer treated as duplicates. `JSON.stringify` serialized function components as `[null]` and object components as `[{}]`, so the second screen's registration was silently dropped and its key did nothing. Components now receive a stable engine-local id for the fingerprint.
- A plain binding in an earlier layer element no longer preempts a sequence owned by a sibling, and the sequence no longer fires alongside it. Priority handlers (auto-tab, wildcard fallback, multi-key sequences) now run across every active element before ordinary bindings, in both regular and modal layers. Previously the sequence's first and next keys also ran the sibling's plain binding, and the outcome depended on `applyElement` order.
- A `Mouse` dropped without `destroy()` is now collected, so the `FinalizationRegistry` safety net can remove its stdin listener, restore raw mode, and turn mouse reporting off. The data listener and the registry's held value no longer close over the `Mouse` or its `TTYController` (the handler reads a shared paused-state object, and the convenience callback captures the event manager instead of `this`); previously the input stream retained the instance forever.
- Mouse reports split across reads are no longer dropped. The parser returns a trailing fragment only while it is still a valid prefix (`\x1b`, `\x1b[`, an incomplete SGR/ESC report), and `MouseEventManager` prepends it to the next chunk; complete reports in the same chunk are still emitted immediately. Invalid or overlong fragments are discarded instead of swallowing later input, and pause, `disable()`, `destroy()` and `reset()` clear the buffer.
- A pending sequence now survives only while the environment it started in still holds. Real focus changes (`focusSet` to another target, `focusNext` / `focusPrev` moving, `kickFocusGroup`, `focusUnregister` removing the focused target, `activateFocusGroup` giving a group its first focus, and built-in Tab rotation on pages and elements) cancel it; no-op focus calls no longer clear an in-progress sequence. Continuation also re-checks the starting `focusId` and, on pages, `stopsWorkingAfterLayerAppearing`, so a missed clearing path cannot fire a stale sequence.
- A sequence gated off by `when` no longer starts when it also has `focusId` or `stopsWorkingAfterLayerAppearing`. Those options returned early and skipped the `when` check, so the sequence swallowed the first key and the plain binding never saw it. The gates are now ANDed, matching the documented `when` relationship.

### Breaking Changes
- `KeyReleaseWhenChainInterrupted` is no longer read. Rename every occurrence to `SwallowKeyWhenChainInterrupted`; the value semantics are unchanged (`true` = swallow the breaking key).

### Tests
- `src/keyboard-engine/tests/composition/base/composition-edge.test.ts` and `composition-regression.test.ts` use the new option name.
- `composition-regression.test.ts` covers a same-key head/terminator (`execute` and `isEndKey`), the undo buffer recording the chain once, an `exclusive` head no longer swallowing later keys, unrelated keys still starting their own chain, an interrupted mapping target not starting a composition head, function- and object-component `category` entries surviving registration side by side, and the `category` filter itself (omitted / `"*"`, listed screens, `[]`, and no top screen).
- `src/keyboard-engine/tests/processors/base/layer-sequence-priority.test.ts` covers both element orders, the sequence's first and completion keys, plain bindings when no sequence matches, broadcast among plain elements, the same priority inside a modal layer, and a priority handler suppressing the same element's plain binding.
- `src/keyboard-engine/tests/xterm-mouse/core/base/mouse-gc-cleanup.test.ts` drops an enabled `Mouse` without `destroy()` and asserts it is collected under `--expose-gc`; reverting either closure capture turns it red. The CI test run now passes `--expose-gc` so the GC cleanup tests are no longer skipped.
- `src/keyboard-engine/tests/xterm-mouse/parser/base/ansiParser.test.ts` splits SGR and ESC reports at every byte boundary, covers a lone trailing ESC, an incomplete CSI introducer, impossible prefixes, a legacy byte outside `escPattern`'s range, and multiple reports with a trailing prefix.
- `src/keyboard-engine/tests/xterm-mouse/core/base/mouse-chunked-input.test.ts` drives `MouseEventManager` with two- and three-chunk reports, split-release clicks, pause/`clearPending`/`reset`, and asserts real parser output instead of a mock.
- `src/keyboard-engine/tests/xterm-mouse/core/base/mouse-chunked-lifecycle.test.ts` drives a real `Mouse` through `pause()`/`resume()`, `disable()`/`enable()` and `destroy()`, asserting a half-received report is discarded.
- `src/keyboard-engine/tests/engine/base/sequence-when-filter.test.ts` covers `focusId` and `stopsWorkingAfterLayerAppearing` with `when=false` on a page, the `when=true` control, and `focusId` inside a layer element.
- `src/keyboard-engine/tests/engine/base/focus-pending-consistency.test.ts` covers no-op vs real focus changes, named groups, page/element Tab rotation (including not clearing a sibling element's pending), the continuation re-check, and layer appearance; `LayerManager.test.ts` expectations now use a real focus change instead of a no-op call.
